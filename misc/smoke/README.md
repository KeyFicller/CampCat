# 烟测与回归验收

完整建图烟测：

```sh
./build/campcat --smoke misc/smoke/demo.txt config.json
```

每次生成独立的 `smoke/<时间戳>/library/` 和 `logs/replay/`。运行期间保留全部审计，
不再因默认只留 20 次回放而丢失早期动作的证据。模拟器、模型和工具仍使用配置中的设置。
本轮不会改动真实技能库；烟测证据随目录保留，可在分析结束后清理整个目录。

模型正常结束只表示交互结束。以下情况都使进程返回 1：图有问题、清单要求的
锚点/边/动作缺失、边没有成功回执、动作没有实际输入及其后的成功断言，或者要求
验证的场景未覆盖。动作 `no_change` 本身不判失败，仍需用具体完成状态判断结果。

离线重新验收已有证据，无需模型或设备：

```sh
./build/campcat --verify-smoke <library目录> <含run-*目录的审计目录> [expect.json]
```

验收器检查审计中的源码是否与当前文件一致；脚本、golden 或 PNG 在回执之后被修改，
旧回执不再验证当前版本。不同次调用的输入、断言不能拼成一次成功。损坏或截断的审计
会报告错误。审计说明执行路径；模板是否代表正确业务状态，仍须由用例明确。
新审计还保存每次匹配所用 PNG 的内容指纹；文件被删除，或内容变化但保留原修改时间，
旧回执都会失效。历史审计没有指纹时只能检查文件存在和修改时间，不能追溯证明
复制审计前的模板内容始终没变。
每条边应单独 `run` 验证；仅经由 `goto` 内部尝试过的边不计入逐边验收，避免外层
捕获导航失败后被误算成功。

`demo.expect.json` 是 Demo 的固定清单，不是通用引擎规则。`--smoke` 自动读取同名
`<清单名>.expect.json`；离线验收通过最后一个参数显式指定。每个图可以声明：

- `anchors`、`edges`、`actions`：必须存在的名称，均不含图名前缀。
- `cases`：资源动作的 `ready` 和 `done` 模板文件名。要求三种独立证据：
  实际输入后断言命中 `done`；无输入、已识别 `done` 而成功返回；两个模板均未命中、
  无输入而返回 `script_failed`。负例可以直接失败结束，也可在外层 `if (run(...))` 捕获。
- `observations`：输入后必须实际识别到的模板，例如加载中界面的 `loading.png`。
  只看到原页面不能证明过渡画面出现过。

这份清单验证应用内四个 page 的 12 条导航边，以及资源动作和模拟弹窗、加载；
不覆盖桌面冷启动，也不允许为获取初态去重置真实游戏账号。初态不可重建、未观察到
加载画面或未覆盖负例时，保留 `unverified`，不把模型的完成宣称当作验收结果。

日常代码回归使用 `misc/scripts/test.sh`，其中 `GoldenClaim` 用真实解释器跑提示词中
的动作示例，分别覆盖可领取、已领取和控件缺失。全量建图和已存脚本回放应分开计时；
未重跑同模型、同配置用例前，不据测试通过宣称提速比例。
